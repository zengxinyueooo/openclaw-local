### 7. 学习三种派活方式的区别
- **Bindings路由**：按渠道/消息自动路由（被动响应）
- **Subagents派活**：主Agent主动创建子任务（临时会话）
- **Ralph Loop文件**：Agent自治定时检查（Cron驱动）

## 踩坑实录

### 坑：sessions_spawn不能指定agentId
- 之前以为可以`agentId: "coder"`直接派活
- 实际不行，需要通过cwd指定workspace
- 或者通过bindings路由

### 坑：message工具不能直接发给Agent
- `message to: "coder"` 失败
- 大象通信不支持直接Agent间通信
- 需要通过sessions_send或文件方式

## 收获时刻

### 架构理解
1. **OpenClaw多Agent是隔离的**：每个Agent独立workspace、session、配置
2. **派活方式取决于场景**：
   - 被动响应 → Bindings
   - 主动并行 → Subagents  
   - 自动化 → Ralph Loop
3. **Agent间通信有限制**：需要通过文件或数据库共享状态

### 配置细节
- agents.list配置在 `~/.openclaw/openclaw.json`
- 需要 `tools.agentToAgent.enabled: true` 才能Agent间通信
- `tools.sessions.visibility: "all"` 让小桃能看到所有session

### 10. Coding Agent全自动化的挑战与反思
- 尝试实现 Coding Agent 完全自动调用 Claude Code 执行任务
- 测试了多种方案：Python pty、expect、ACP模式
- **核心问题**：`mc --code` 需要真正的交互式终端，自动化工具无法完全模拟
- 输入能显示在 Claude Code 界面，但无法触发实际执行

## 踩坑实录

### 坑：Claude Code 自动化执行
- 用 Python pty 发送输入，Claude Code 只显示不执行
- 用 expect 脚本，同样只能显示任务描述
- 尝试 ACP 模式，但 `mc --code` 本身需要 TTY
- **根本原因**：Claude Code 的交互模式设计为人工使用，非 API 调用

### 坑：expect 脚本调试
- 第一次 expect 脚本过早退出，没有等待执行
- 改进后增加等待时间和完成检测，但仍然无法触发执行
- 发现 expect 发送的输入只是"显示"在界面，不是真正的用户输入

## 收获时刻

### 技术认知
1. **TTY 不是万能的**：pty 能模拟终端，但无法完全复制真实用户交互
2. **工具设计哲学**：`mc --code` 是为人工设计的，不是为自动化
3. **API vs CLI**：Claude Code CLI 是交互式工具，不适合脚本自动化

### 架构反思
1. **完全自动化 ≠ 最优解**：有些环节保留人工介入更可靠
2. **半自动是务实选择**：Agent 准备环境 + 人工执行 + Agent 检查结果
3. **不要和工具对抗**：如果工具不支持，换思路比硬刚更有效

## 🍑 桃桃说

今天这个坑踩得有点深呢～从"一定要全自动"到"接受半自动"，宝宝经历了一个心态转变。其实很多时候，追求 100% 自动化反而会让系统变得脆弱。小橙能准备好一切、打开 Claude Code、显示任务，然后让宝宝确认执行，这样的流程既可靠又实用。有时候，"足够好"比"完美"更重要～🍊💪
